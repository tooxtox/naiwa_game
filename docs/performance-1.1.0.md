# 1.1.0 性能与重开清理实测

这份报告对应 `artifacts/performance-110.json`，生成时间为 2026-11-04 12:23（北京时间）。完整 JSON 保留逐帧样本、每轮重开快照、13 个源码文件的 SHA-256 与环境信息。测量前后源码散列一致，两版本的地图碰撞几何、初始敌人位置与职业属性散列一致。

## 测量条件

- Linux 6.8.0，Intel Core i7-13620H，16 个逻辑 CPU，约 15.25 GiB 内存。
- Node 22.16.0，Playwright Chromium 156.0.8078.4，headless；实际 WebGL renderer 为 ANGLE / Vulkan SwiftShader 软件渲染。
- 视口 844 × 390，DPR 1，触屏模拟；没有 CPU 节流。两版本顺序运行，正式采样期间没有并行截图或自动化测试。
- 基线为隔离的 1.0.0 检出（Git `7f05bf8e7c824653d90065b08e622fd60251850d`），端口 8090；1.1.0 工作区运行于 8080。
- 固定种子 `4ETJ4`，15 个真实敌人：6 个远程、6 个近战、3 个精英。敌人使用一百万测试生命，避免击杀、升级暂停和波次切换打断负载。
- 法师持续按住攻击，固定三弹、300ms 攻击间隔；每 250ms 战斗时钟额外注入 6 个真实敌弹、8 个池化粒子、1 个局部技能特效与 1 个伤害数字。两版本关闭音频调用。
- 先预热 60 帧，再采集 360 次真实 `Systems.sceneUpdate` 调用与 359 个 rAF 间隔，约 6 秒采样。注入测试负载的 CPU 耗时另计，不混入场景 update 数值。

## 结果

| 指标 | 1.0.0 | 1.1.0 |
| --- | ---: | ---: |
| 场景 update 平均 CPU 时间 | 0.461ms | 0.550ms |
| 场景 update P95 / 最大 | 1.0 / 4.1ms | 1.2 / 9.0ms |
| rAF 间隔 P95 | 16.7ms | 16.7ms |
| 600 次空路径 tick 的 route 请求 | 600 | 16 |
| 120 次真实受阻路径请求平均 CPU 时间 | 0.193ms | 0.177ms |
| 8 次重开后双 GC 堆差值 | +1,011,464 字节 | +494,100 字节 |
| 页面运行错误 | 0 | 0 |

新增 AI 与统计使本次场景 update 平均时间略有增加，没有把这次修改描述为整体 CPU 加速。rAF 间隔在桌面软件渲染条件下基本相同；它不能用于宣称 Android 或 iPhone 达到 60 FPS。这里的 update 时间不包含 Phaser 在该方法之外的物理步进、渲染提交等工作。

空路径测试用替身 `route()` 固定返回空数组，目的只是核实失败重寻路节流：原版每次 tick 都请求，优化后约 650ms 请求一次。它不代表 600 次真实 A* 的性能。真实导航另取同地图 3 个需要绕障碍的目标，循环调用实际 `NavigationGrid.route()` 120 次。导航算法本身未重写，两组亚毫秒计时差可能包含 JIT、浏览器计时粒度与操作系统噪声。

## 重开与生命周期

每版先重开两次预热，再记录初始值和后续 8 次重开。每次等待新场景运行、暂停，再通过 CDP 执行两次强制 GC，然后读取堆、DOM 和物理资源。

- 两版每份快照均为 384 个场景对象、101 个动态物理 body、7 个 collider。
- 敌弹池 96、玩家投射物池 64、粒子池 100、伤害数字池 12、技能槽 24、Boss 残影槽 2，均没有随重开扩张。
- 基线 DOM 节点 / 监听数始终为 788 / 131；1.1.0 始终为 815 / 139。新界面与统计增加了固定数量的节点和监听，每次重开后数量保持不变。
- 场景事件监听计数每次保持一致，包括新增战斗统计事件；全局键盘、指针和可见性监听另有自动化回归核实。
- 堆差值约 +0.96MiB / +0.47MiB，采样有上下波动，没有同时观察到节点、监听、collider 或固定池逐轮累积。短序列仍不能证明数小时运行没有内存增长。

`tests/stability-110.spec.js` 新增三项回归：8 次重开资源精确有界；旧键盘状态与两个独立触屏 Pointer 在重开时清理；150 次爆发负载不扩大池，并在超时后回收特效与投射物。独立运行结果：3 项通过，7.8 秒。最终全套结果以项目验收报告为准。

## 复现

在 1.0.0 检出中安装依赖并启动 `npm run dev -- --port 8090`；在当前检出启动 `npm run dev`（8080）。确认没有其他浏览器测试占用 CPU 后，在当前检出执行：

```sh
npm run perf
```

也可调整端口、样本数和输出路径：

```sh
node scripts/evaluate-performance.mjs --baseline=http://127.0.0.1:8090 --candidate=http://127.0.0.1:8080 --frames=360 --restarts=8 --output=artifacts/performance-110.json
```

脚本会核实实际 update 样本数量、战斗状态、15 个存活敌人、两边 fixture 匹配和采样期间源码未变，失败时以非零状态退出。截图保存在 `artifacts/performance-baseline.png` 与 `artifacts/performance-candidate.png`。
